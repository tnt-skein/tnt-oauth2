# Вход через чужую службу: OAuth 2.0

OAuth 2.0 выдаёт доступ, а не личность: служба — GitHub, Google,
корпоративный вход — пускает посетителя к себе и отдаёт приложению токен.
`tnt-oauth2` — клиент такой службы: вход посетителя потоком с кодом
(RFC 6749, §4.1) с PKCE и `state`, токены самого клиента, обновление
и поставщик живого токена, а всё, что пришло снаружи негодным, — отказ
парой с родом.

```lua
local oauth2 = require('tnt.oauth2')

local github = oauth2.new({
    name = 'github',
    client_id = os.getenv('GITHUB_CLIENT_ID'),
    client_secret = os.getenv('GITHUB_CLIENT_SECRET'),
    authorize_url = 'https://github.com/login/oauth/authorize',
    token_url = 'https://github.com/login/oauth/access_token',
    userinfo_url = 'https://api.github.com/user',
    redirect_uri = 'https://app.example.org/auth/github/callback',
    scopes = { 'read:user' },
    profile = function(user)
        if type(user.id) ~= 'number' then
            return nil, 'служба не назвала id'
        end

        return { subject = tostring(user.id), name = user.login }
    end,
})

local address = github:authorize(request.session)                    -- уводим посетителя туда
local assertion, grant = github:finish(request.session, request.query) -- он вернулся
```

## Зачем пакет

Поток с кодом — пять шагов и два запроса, и каждый шаг, сделанный
«на глаз», открывает дверь. Пакет держит их в одном месте; всё сверено
на Tarantool 3.8.0 с настоящей службой OAuth 2.0.

1. **`state` в сессии и сверка за постоянное время** (RFC 9700, §2.1).
   Без него ссылка возврата с чужим кодом, подсунутая посетителю, вводила
   бы его в учётную запись того, кто её подсунул.
2. **PKCE только `S256`** (RFC 7636). Код, перехваченный по дороге —
   журнал прокси, заголовок `Referer`, — без проверочного кода на токены
   не меняется. `plain` не шлётся: при нём вызов и есть проверочный код.
3. **Начатый вход одноразовый и живёт пятнадцать минут.** Возврат забирает
   его из сессии до всякой сверки: второй возврат с тем же адресом — отказ,
   а не второй вход.
4. **Адрес возврата — ровно из настроек**, адреса службы — только
   `https://`. Служба сверяет адрес возврата точным совпадением, а ключ
   клиента и код не должны ехать открытым текстом.
5. **Токены — учётные данные.** Их нет ни в удостоверении, ни в тексте
   отказа: причину службы пакет пропускает через вычёркивание, и код,
   токен или ключ клиента, повторённые службой, там не появятся.

О личности пакет не знает: удостоверение из профиля службы собирает
функция приложения `profile`, а учётную запись по удостоверению находит
само приложение. Зависит от [`tnt-http`](https://github.com/tnt-skein/tnt-http)
(запросы к службе, кодирование адреса), [`tnt-hash`](https://github.com/tnt-skein/tnt-hash)
(вызов PKCE и сверка `state`), [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(проверки аргументов), [`tnt-clock`](https://github.com/tnt-skein/tnt-clock)
(стенные часы) и [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена часов и случайных байтов в проверках). От
[`tnt-jwt`](https://github.com/tnt-skein/tnt-jwt) пакет не зависит: токен
доступа OAuth 2.0 клиенту непрозрачен (RFC 6749, §1.4). Опознающий токен
OpenID Connect, если служба его прислала, лежит в `grant.extra.id_token`,
и сверяет его тот, кто строит вход OpenID Connect поверх этого же потока
с кодом.

## Как пользоваться

| Действие | Что делает |
|---|---|
| `oauth2.new(настройки)` | клиент службы; в сеть не ходит |
| `клиент:authorize(сессия[, { scopes, params }])` | начинает вход: `state` и проверочный код — в сессию, адрес службы — наружу |
| `клиент:finish(сессия, параметры)` | весь возврат: удостоверение и токены либо `nil, err` |
| `клиент:callback(сессия, параметры)` | только сверка `state` и токены за код |
| `клиент:userinfo(токены)` | профиль у точки профиля либо `nil, err` |
| `клиент:refresh(токен обновления[, { scopes }])` | новые токены (RFC 6749, §6) |
| `клиент:credentials([{ scopes }])` | токены самого клиента (`client_credentials`, §4.4) |
| `клиент:source({ grant \| refresh_token \| credentials = true })` | поставщик живого токена: функция без аргументов |
| `STATE_TTL`, `MARGIN`, `UNKNOWN_TTL` | срок начатого входа, запас обновления, срок токена без срока: 900, 60 и 300 с |
| `STATE`, `DENIED`, `REJECTED`, `MALFORMED`, `UNAVAILABLE`, `REFUSED` | роды отказа |

### Вход посетителя

Два адреса приложения: один уводит посетителя к службе, второй его
принимает. Сессия — объект посетителя с методами `put(ключ, значение)`
и `pull(ключ)`; `pull` отдаёт значение и тут же стирает его. Начатый вход
лежит в сессии под ключом `oauth2.<имя службы>`, поэтому сессия нужна своя
у каждого посетителя и живущая не меньше пятнадцати минут. Больше пакет
от неё ничего не берёт.

```lua
local log = require('log')

-- GET /auth/github: уводим посетителя к службе
local function start(request)
    return { status = 303, headers = { location = github:authorize(request.session) } }
end

-- GET /auth/github/callback: он вернулся
local function callback(request)
    local assertion, grant = github:finish(request.session, request.query)

    if assertion == nil then
        local err = grant -- при отказе второе значение — отказ, а не токены

        log.warn('вход через github не удался: %s', tostring(err))

        return { status = err.kind == oauth2.UNAVAILABLE and 503 or 401 }
    end

    -- учётная запись приложения — по паре provider и subject
    local account = accounts.find_or_create(assertion.provider, assertion.subject, assertion.name)

    request.session:put('account_id', account.id)

    return { status = 303, headers = { location = '/' } }
end
```

После входа сессии нужен новый опознаватель: иначе опознаватель,
подсунутый посетителю заранее, достался бы вошедшему. Это забота сессии,
а не пакета, — пакет только кладёт в неё начатый вход и забирает его.

Адрес службы — `authorize_url` с параметрами в постоянном порядке:
`client_id`, `code_challenge`, `code_challenge_method=S256`,
`redirect_uri`, `response_type=code`, `scope` через пробел (`%20`)
и `state`. Свои параметры службы — `prompt`, `login_hint`,
`access_type=offline` у Google — и свои права на этот вход задаёт второй
аргумент; перекрыть параметры самого входа нельзя:

```lua
github:authorize(session, { scopes = { 'read:user', 'user:email' }, params = { prompt = 'consent' } })

github:authorize(session, { params = { state = 'mine' } })
--> app.lua:3: настройки входа.params.state ставит сам вход
```

`finish` отдаёт при удаче удостоверение и вторым значением токены,
при неудаче — `nil` и отказ. Удостоверение — запись о том, кто вошёл,
через какую службу и когда. Так оно выглядит после входа на службе
стенда проверок:

```lua
local assertion, grant = client:finish(session, query)
assertion
--> {
-->     provider = 'mock',
-->     subject = '6f1c8f14-…',
-->     methods = {},
-->     authenticated_at = 1790330000.52,
-->     claims = { iss = 'http://127.0.0.1:18480/default' },
--> }
grant
--> {
-->     access_token = 'eyJraWQiOi…',
-->     token_type = 'Bearer',
-->     expires_at = 1790333599.53,
-->     refresh_token = 'c575c0a9-…',
-->     extra = { id_token = 'eyJraWQiOi…' },
--> }
```

`issuer` у удостоверения пуст: выдавшего у OAuth 2.0 нет, и ключ
учётной записи у приложения — пара `provider` и `subject`. `methods`
пуст, если `profile` не назвала их сама: служба не говорит, чем посетитель
доказал себя, а пустой список и значит «неизвестно» (RFC 8176).
`authenticated_at` — миг ответа службы по стенным часам, секунд эпохи.
Токены приложению нужны, только если оно ходит к службе от имени
человека; тогда их хранят как учётные данные — там, где их не видит
посетитель: сессия, которая целиком лежит в куке, годится для них только
зашифрованной.

### Профиль и удостоверение

Стандартного ответа «кто это» у OAuth 2.0 нет, и какое поле у службы
постоянно (`id`, а не почта: почту меняют), знает только тот, кто её
подключает. Поэтому удостоверение собирает `profile(userinfo, grant)`:

| `profile` отдаёт | Что это | Итог `finish` |
|---|---|---|
| `{ subject, name, methods, claims }` | пользователь назван | удостоверение |
| `nil` либо `nil, причина` | служба ответила, а пользователя не узнать | отказ `refused` |

`userinfo` — объект JSON точки профиля; службе без неё (`userinfo_url`
не задан) достаётся `nil`, и пользователь ищется в `grant.extra` —
прочих полях ответа точки токенов. `claims` по умолчанию — весь профиль.

Вид ответа `profile` сверяется: поля закрыты, `subject` — строка
до 255 байт без управляющих знаков, `name` — строка, `methods` — список
строк. Промах — бросок: `profile` пишет программист, и данные службы
он обязан проверить сам.

```lua
profile = function(user)
    return { id = user.id }
end
--> app.lua:9: profile: ключа «id» нет, есть claims, methods, name, subject

profile = function(user)
    return { subject = user.id }          -- число: GitHub отдаёт id числом
end
--> app.lua:9: profile.subject — непустая строка, а не число
```

### Настройки

| Настройка | Что это | По умолчанию |
|---|---|---|
| `name` | имя службы: `provider` удостоверения и ключ сессии; строчная латиница, цифры, `_`, `.`, `-`, с буквы, до 64 знаков | обязательна |
| `client_id` | опознаватель клиента у службы | обязателен |
| `client_secret` | ключ клиента; у публичного клиента его нет | нет |
| `client_auth` | как клиент подтверждает себя: `client_secret_basic` либо `client_secret_post` | `client_secret_basic` |
| `token_url` | точка токенов | обязательна |
| `authorize_url`, `redirect_uri` | точка авторизации и адрес возврата — только вместе | нет: клиент без входа посетителя |
| `userinfo_url` | точка профиля | нет |
| `scopes` | права, которые просит вход и токены клиента | нет |
| `profile` | функция удостоверения, нужна `finish` | нет |
| `http` | клиент `tnt-http` либо таблица с `request(opts)` | свой: без переходов |

Настройки сверяются при сборке, и промах — бросок на строке вызывающего:

```lua
oauth2.new({ name = 'GitHub', client_id = 'app', token_url = 'https://id.example.org/token' })
--> app.lua:1: настройки.name — строчная латиница, цифры, «_», «.» и «-», с буквы, а не «GitHub»

oauth2.new({ name = 'idp', client_id = 'app', token_url = 'http://id.example.org/token' })
--> app.lua:2: настройки.token_url — адрес https://, а http:// — только к 127.0.0.1 и [::1], а не «http://id.example.org/token»

oauth2.new({ name = 'idp', client_id = 'app', token_url = 'https://app:secret@id.example.org/token' })
--> app.lua:3: настройки.token_url: имя и пароль в адресе не пишут — ключ клиента задают client_secret
```

**Адреса — только `https://`.** Точка токенов получает ключ клиента
и код, точка авторизации — `state`, и RFC 6749 требует TLS у обеих (§3.1,
§3.2). `http://` годится только к петле — `127.0.0.1` и `[::1]`: на ней
стоят стенд и проверки. Имя `localhost` не годится: его разрешает чужая
настройка узла (RFC 8252, §8.3). В адресе нет ни имени с паролем — адрес
уходит в журнал клиента HTTP, — ни `#`: часть после решётки на сервер
не уходит вовсе.

**Клиент подтверждает себя заголовком `Basic`** (`client_secret_basic`):
этот способ обязана понимать всякая служба (§2.3.1). Имя и ключ перед
склейкой кодируются как в форме, и ключ с двоеточием не разрезается
не там. `client_secret_post` кладёт их в тело — так просят службы,
не читающие заголовок. Публичный клиент без ключа — приложение
на устройстве посетителя — называет себя `client_id` в теле, и от
перехвата кода его бережёт PKCE.

**Клиент HTTP по умолчанию — без переходов.** Код годится один раз,
а переход 307 унёс бы тело с кодом и ключом клиента на другой адрес: ответ
3xx точки — отказ. POST клиент HTTP не повторяет никогда, и код не уйдёт
к службе дважды. Свой клиент — тоже аргументом: с корнями доверия,
сроком, прокси.

## Отказ

Всё, что пришло снаружи, — отказ парой: `nil, err`, где `err` — таблица
с родом `kind`, текстом `message` и кодом службы `code`, если он был.
Строкой, в склейке и в `json.encode` отказ — свой текст.

| Род | Когда |
|---|---|
| `state` | в сессии нет начатого входа, вход начат дольше 15 минут назад, `state` не совпал либо не пришёл |
| `denied` | служба отказала во входе: `error` в адресе возврата — посетитель нажал «отмена», прав нет |
| `rejected` | служба отвергла запрос: код выдан под другой проверочный код, токен обновления отозван, клиент не тот, чужой токен у точки профиля, ответ 3xx и 4xx |
| `malformed` | ответ не по протоколу: не объект JSON, нет `access_token`, токен не Bearer, срок не число больше нуля, в адресе возврата нет кода |
| `unavailable` | служба не ответила либо занята: сеть, срок, 408, 429, 5xx |
| `refused` | `profile` не узнала пользователя |

```lua
local grant, err = client:callback(session, query)   -- проверочный код не тот
err.kind
--> rejected
err.code
--> invalid_grant
tostring(err)
--> обмен кода: служба ответила 400 — invalid_grant: invalid_pkce: code_verifier does not compute to code_challenge from request

client:callback(session, { state = 'чужой', code = 'x' })
--> nil, ответ службы не к этому входу: state не совпал
```

Посетителю отвечают по роду: `unavailable` — 503, вход сорвался
по вине службы, и посетитель тут ни при чём; остальные роды — 401.
Отказ службы не стоит засчитывать попыткой подбора: служба, не ответившая
за срок, — не неверный пароль.

**Ошибка OAuth узнаётся по полю `error`, а не по коду ответа.** Часть
служб отвечает ею с кодом 200 (`{"error":"bad_verification_code"}`),
и такой ответ — отказ, а не токен. **Тайн в тексте нет:** из причины
службы вычёркиваются код, проверочный код, токены и ключ клиента этого
обращения, управляющие знаки становятся точкой, длина — не больше
200 байт. Тело ответа в отказ не попадает никогда: служба, не понявшая
`Accept: application/json`, отдаёт токен формой, и начало такого тела —
сам токен.

```lua
-- служба повторила присланное в своей причине
tostring(err)
--> обмен кода: служба ответила 401 — invalid_client: code [скрыто] with verifier [скрыто] for [скрыто]
```

## Токены клиента, обновление и поставщик токена

Токены нужны не только входу посетителя. Узел ходит в чужое API сам —
почта Microsoft 365, очередь в облаке, — и тогда токен выдаётся самому
клиенту (`client_credentials`), а человек, однажды давший согласие,
оставляет токен обновления:

```lua
local grant = assert(client:credentials({ scopes = { 'mail' } }))
grant.token_type
--> Bearer

local fresh = assert(client:refresh(grant_of_visitor.refresh_token))
```

`refresh` оставляет прежний токен обновления, если служба не прислала
нового: иначе первое же обновление теряло бы право на второе. Срок
токена — миг стенных часов `expires_at`: `expires_in` отсчитан от
ответа, и сверять его удобно с часами. Служба, не назвавшая срока, даёт
`expires_at = nil`.

**Поставщик** — функция без аргументов: она отдаёт живой токен строкой
либо `nil, err`, и тот, кто её зовёт, о сроках не знает ничего.

```lua
local token = google:source({ refresh_token = stored_refresh_token })   -- токены человека
local robot = microsoft:source({ credentials = true, scopes = { 'https://outlook.office365.com/.default' } })
local after_login = github:source({ grant = grant })                    -- сразу после finish

token()
--> ya29.a0AfB…
```

- **Новый токен — до срока, а не после отказа.** Токен, отданный
  за секунду до срока, умер бы посреди входа почты, а отказ сервера почты
  поставщик не видит. Новый берётся за минуту до срока (`MARGIN`), а у
  короткого токена — на половине его жизни.
- **Служба, не назвавшая срок**, получает пять минут (`UNKNOWN_TTL`):
  токен без срока мог быть отозван, и спросить новый дешевле, чем
  проверять старый.
- **Одно обновление на всех.** Файберы, которым токен понадобился в миг
  обновления, ждут его, а не шлют своё: у службы, меняющей токен
  обновления на каждом шаге (RFC 9700, §4.14.2), второе обновление тем же
  токеном отозвало бы всю цепочку. Отказ достаётся всем ждавшим — тем же
  отказом.
- **Живой токен лучше отказа.** Не удалось обновиться за минуту до
  срока — отдаётся прежний, пока он годен: служба, лежащая минуту,
  не роняет почту узла.
- **Токен обновления, сменённый службой**, идёт в следующее обновление.

Ровно одно из трёх: `grant` (у него обязан быть `refresh_token`,
иначе через час обновить его нечем), `refresh_token` либо
`credentials = true`; иное — бросок.

### Почта по XOAUTH2

Gmail и Microsoft 365 не пускают ящик паролем: вход — XOAUTH2 с токеном
OAuth 2.0. [`tnt-mail`](https://github.com/tnt-skein/tnt-mail) берёт
поставщика паролем и зовёт его перед каждым входом — по SMTP, IMAP
и POP3 (его документ, раздел «Способы входа»):

```lua
local token = google:source({ refresh_token = stored_refresh_token })

mail.configure({
    from = 'node@example.org',
    username = 'node@example.org',
    password = token,
    smtp = { host = 'smtp.gmail.com', tls = 'starttls', auth = 'xoauth2' },
    imap = { host = 'imap.gmail.com', tls = 'direct', auth = 'xoauth2' },
})
```

Не получив токена, почта сервер не будит: письмо — отказ «пароль
не получен» со словами отказа службы, и та же причина ложится в журнал
записью «письмо не отправлено»:

```lua
mail.send({ to = 'duty@example.org', text = 'x' })     -- точка токенов не отвечает
--> false, пароль не получен: обновление токена: служба не ответила: сервер не ответил: Could not connect to server (код 595)
```

## Проверено на настоящей службе

| Что | Как |
|---|---|
| вход с PKCE и `state` | адрес службы → переход с кодом → `finish`: удостоверение, `access_token`, `refresh_token`, `id_token` в `extra` |
| код под чужой проверочный код | служба отвечает 400 `invalid_grant: invalid_pkce…`, отказ `rejected` |
| чужой `state` | отказ `state` до обращения к службе |
| обновление | новый `access_token`, поставщик по `grant` отдаёт прежний, пока тот жив |
| токены клиента | `client_credentials` с правами `mail` |
| чужой токен у точки профиля | 401 `invalid_token`, отказ `rejected` |

## Чем пришлось поступиться

- **Один начатый вход на службу в сессии.** Второй вход через ту же
  службу, начатый в соседней вкладке, заменяет первый, и возврат первой
  вкладки — отказ `state`. Держать список начатых входов значило бы держать
  и его предел, а вход в двух вкладках разом — редкость.
- **`http://` — только к петле.** Служба во внутренней сети без TLS
  с пакетом не заговорит: у неё ключ клиента и код ехали бы открытым
  текстом. Стенду хватает петли.
- **Параметр `iss` в адресе возврата (RFC 9207) не сверяется.** От
  подмены службы на возврате бережёт свой адрес возврата у каждой службы
  (RFC 9700, §4.4.2) — отсюда и `redirect_uri`, обязательный у каждого
  клиента, и ключ сессии, свой у каждой службы.
- **Токен только Bearer.** Токен другого типа клиент предъявить не умеет;
  тип, которого служба не назвала, считается Bearer — так отвечают
  службы, забывшие обязательное поле.
- **Поставщик не видит отказа сервера.** Токен, отозванный службой
  до срока, поставщик отдаёт до срока: узнать об отзыве ему неоткуда,
  кроме самой службы. Худшее — час отказов входа у почты.
- **Удостоверение без `methods`.** Чем посетитель доказал себя у службы,
  OAuth 2.0 не говорит; правило «только со вторым фактором» по такому
  входу не выполнится, пока `profile` не назовёт `methods` сама — по
  данным службы, если она их даёт.
- **Подписи клиента токеном (`private_key_jwt`, `client_secret_jwt`)
  нет.** Подписи открытым ключом во встроенном `crypto` нет, а обычным
  службам хватает ключа клиента заголовком `Basic` либо в теле запроса.

## Проверки

Проверки лежат в `test/` и идут на luatest. Служба подменяется двойником
клиента HTTP — таблицей с `request`: он отдаёт ответы по порядку и помнит
запросы, и видно, что именно ушло к службе: форма, заголовок `Basic`,
адрес. Вызов PKCE сверен с вектором RFC 7636, приложение B. Подменяются
только часы и случайные байты — сроки сверены на самой границе. Что тайны
не попадают в журнал, проверено настоящим клиентом HTTP с подменённым
libcurl: код, проверочный код, `state`, токены и ключ клиента
не встречаются ни в одной записи журнала и ни в одном отказе.

Живая проверка `oauth2_live_test.lua` идёт против mock-oauth2-server
в докере — настоящей службы, которая сверяет проверочный код PKCE,
обновляет токены и выдаёт токены клиенту:

```sh
make oauth2-up      # mock-oauth2-server на 127.0.0.1:18480, вход без окна
make test
make oauth2-down
```

Без службы живые проверки пропускаются: гейты не должны зависеть
от докера. Проверок — 78, из них 6 живых; покрытие строк — 100 %,
убитых мутантов — 100 % (385 мутантов в десяти модулях; в фасаде
мутировать нечего).
